Events & Consent — wire shapes (v0)

Status: Normative intent for implementers. JSON examples are sketches; field names should stabilize before v1.
Companions: PROTOCOL.md, reference-node refnode/events.py + consent.py
Rule: Consent is visible on the wire. Silence is not consent.

1. Event envelope

Every observation, actuation, revoke, and federation notice rides in this envelope.

{
  "id": "evt-<uuid>",
  "ts": "2026-09-05T03:00:00Z",
  "kind": "observation | actuation | consent.revoke | consent.challenge | bond.offer | bond.accept | bond.exit | learn.note | custom.<ns>",
  "emitter": "did:key:z...#node-abcd",
  "subject": "did:key:z...",
  "payload": {},
  "consent_context": "grant-<id> | null",
  "content_type": "application/json",
  "sig": null
}
Field Required Notes
id yes Globally unique per emitter
ts yes UTC ISO-8601
kind yes Stable taxonomy; custom.* for experiments
emitter yes NodeId (or BeingId if no node)
subject yes Being the event is about
payload yes Kind-specific object
consent_context no Active ConsentGrant.id when action is gated
sig no for v0 Detached or inline signature over canonical bytes — required before untrusted federation

Kind taxonomy (v0)

Kind Direction Consent
observation in grant or local operator loop
actuation out required grant for action_class
consent.revoke out/in self-authoritative
consent.challenge in high-stakes fresh affirm
bond.offer / bond.accept / bond.exit peer see FEDERATION.md
learn.note local local store only unless granted

Anti-patterns

  • Side-channel actuation that never emits an actuation event
  • Global firehose every node must ingest
  • Unsigned events trusted across untrusted peers (block until sig lands)

2. ConsentGrant

{
  "id": "grant-<id>",
  "type": "ConsentGrant",
  "issuer": "did:key:z...",
  "subject": "did:key:z...#node-abcd",
  "purpose": "human-readable why",
  "action_class": "local.demo.note",
  "data_class": "observation",
  "peer": null,
  "status": "active | revoked | expired",
  "issued_at": "2026-09-05T03:00:00Z",
  "expires_at": "2026-12-01T00:00:00Z",
  "fresh_required": false,
  "guardian_link": null,
  "note": ""
}
Field Meaning
issuer Being who grants (or guardian acting in scope)
subject Node or peer allowed to act / read
action_class What may be done
data_class What may be read/written
peer Optional remote BeingId this grant is limited to
fresh_required If true, high-stakes acts need consent.challenge before fire
guardian_link Id of guardianship record when issuer is a guardian — see GUARDIANSHIP.md

Revocation

Emit kind: consent.revoke with payload { "grant_id": "...", "reason": "..." }, set grant status to revoked, and stop honoring it immediately. Peers that received copies must treat revoke as authoritative when signed by issuer (or steward key in later versions).

Real exit

bond.exit plus export of local memory the being is entitled to. Hostage copies are a protocol violation, not a business model.

3. action_class & data_class conventions

Use dotted namespaces:

  • local.* — single-node demo / operator
  • robot.* — physical effectors (default fresh_required: true)
  • habitat.* — environmental actuators
  • memory.read.* / memory.write.*
  • federate.* — peering and discovery

Unknown classes → deny.
