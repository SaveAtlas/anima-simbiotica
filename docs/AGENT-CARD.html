Agent Card (v0)

Companions: A2A-MCP-MAPPING.md, FEDERATION.md, reference-node identity/agent-card.json
Rule: Capability advert rooted in ANIMA identity — not a vendor cloud registry.

1. Shape

{
  "protocol": "anima",
  "version": "0.1.0-sketch",
  "beingId": "did:key:z...",
  "nodeId": "did:key:z...",
  "capabilities": ["sense", "remember", "decide", "act", "learn"],
  "streams": ["stream-observations-minimal"],
  "endpoints": [],
  "adapters": { "llm": "optional-stub", "transport": [] },
  "auth": { "mode": "did-key", "landlord_login": false }
}

A2A-style well-known hosting is fine as an adapter path (/.well-known/...) if the card’s beingId/nodeId remain DID-rooted and landlord_login stays false for spine identity.

2. Discovery

  1. Out-of-band / Bond offer carries card URL or inline card.
  2. FederationHint may point to a card index — disposable.
  3. No single mandatory registry.

3. Stability

  • Additive capabilities preferred.
  • Removing a capability: peers must fail soft.
  • Version string tracks card schema, not constitution.

4. Builder

  • Keep generating card on identity create.
  • After ADR-001 migration, card must show distinct beingId/nodeId.
  • Never require big-tech landlord login to fetch a card.

5. Soft-fail (S7)

Peers discovering a card MUST:

  1. Ignore unknown capability strings (forward compatible).
  2. If a previously used capability is absent, degrade that feature — do not treat the peer as hostile solely for removal.
  3. Reject the card only if beingId/nodeId missing, landlord_login true for spine identity, or schema-required fields fail validation.

Card version is card schema semver (0.1.0-sketch → 0.2.0-sketch on breaking card fields). Constitution version is separate.
