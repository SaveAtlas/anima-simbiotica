Reuse vs Invent — ANIMA

Companion to: CONSTITUTION.md, PROTOCOL.md
Rule of thumb: Reuse battle-tested open standards for plumbing. Invent only where symbiotic life, multi-kingdom consent, and a voluntary compute mesh have no honest home yet.
Never: reinvent identity/crypto for ego, or invent a closed stack that pretends to be a protocol.

North star

ANIMA is the constitution + consent + multi-being ontology + federation norms that sit above existing open pipes.

We wrap and compose. We do not capture. If a dependency becomes a landlord for identity or memory, we treat it as a disposable adapter and plan the exit.

Reuse (prefer these)

Identity & credentials

Reuse Why ANIMA stance
W3C DIDs Decentralized identifiers without a single registrar-king Root BeingId / NodeId
W3C Verifiable Credentials Portable attestations (guardian links, audits, capability claims) Prove without oversharing
did:key / did:web / open DID methods Practical bootstraps Avoid methods that silently re-centralize
AT Proto identity ideas (portable account, repo-of-self) Humans already need portable social/data selves Steal ideas (portability, user repo); do not make Bluesky the spine

Agent talk & tools

Reuse Why ANIMA stance
A2A-like agent interoperability (Linux Foundation A2A: Agent Cards, task lifecycle, JSON-RPC/HTTP) Agents must talk as peers, not only as tools Adopt patterns; root cards in DIDs; never require one vendor’s agent cloud
MCP (Model Context Protocol) Vertical tool/context access for agents Adapter for tools — not identity, not memory custody
ANP / DID-rooted agent network ideas Open-web complement to enterprise A2A Align federation discovery with DID-first thinking

Data portability & federation patterns

Reuse Why ANIMA stance
AT Proto concepts — portable repos, signed records, lexicon-ish schemas Exit and replication patterns for human-scale data Memory export + selective sync inspiration
ActivityPub / fediverse lessons Long history of federation failure modes (capture, siloed mods, reply chaos) Learn anti-patterns; don’t blindly copy social-only assumptions
IPFS / content addressing (optional) Content-addressed replicas Edge option for shared artifacts — never mandatory

Robots, IoT, habitats

Reuse Why ANIMA stance

MQTT / DDS Pub-sub for sensors and devices Event transport adapter under subscriptions
Matter / Zigbee / local home stacks Local-first device control Prefer local; cloud bridges = disposable adapters

Crypto, transport, encoding

Reuse Why ANIMA stance

Governance & legal patterns (study, don’t copy blindly)

  • Creative Commons / open-spec norms for protocol text
  • Foundation / commons stewardship models (exact entity TBD with Ovie)
  • Right-to-exit and data-portability lessons from GDPR-class regimes — as ethics floor, not as the only jurisdiction

Invent (ANIMA must create)

These are not solved by “just use A2A + DIDs.”

1. Symbiotic life ontology

A first-class model of multi-kingdom participation:

  • Humans, AIs, machines, animals, ecosystems, future habitats
  • Shared vocabulary for interests, harm, care, and representation
  • Not “everything is a user account”

2. Guardian & proxy consent for non-speaking beings

  • Structured guardianship (scope, duties, challenge, succession)
  • Sensor/actuator proxies for animals and ecosystems
  • Explicit conflict handling when human economic interest ≠ dependent being’s interest

3. Consent as the outer contract

Most stacks bolt consent onto ToS. ANIMA inverts that:

  • ConsentGrant / revoke / fresh challenge as wire-visible
  • High-stakes actuation gated by protocol, not by app UI theater
  • Bonds as objects with exit terms

4. Memory custody model for mixed beings

  • Local-first stores for humans and agent runtimes and habitat logs
  • Grants that compose across species/guardian boundaries
  • Learning/training rights never silent

5. Voluntary global compute mesh (edge economy)

  • Optional, consensual compute/storage trades between peers
  • Tiny fees allowed on optional trades only
  • No mandatory cloud; no ads-against-beings business model
  • Mesh discovery without a single landlord switchboard

6. Mycelium growth & anti-capture posture

  • Norms and tests: “can one actor kill the network?” → must be no
  • Adapter purity tests: remove big-tech login adapters — beings still exist
  • Separation rule: company ops stacks may speak ANIMA; they must not become ANIMA

7. Reference loop semantics

sense → remember → decide → act → learn as a portable runtime contract on operator-controlled hardware, with each step mapped to identity/memory/consent/events — not a cloud workflow product.

Gray zone (reuse carefully)

Thing Risk How we touch it
Vendor LLMs Become silent spine for “decide” Swappable model adapters; local models first-class
Push notification services Become choke points Optional; never required for consent or identity
Cloud GPU marketplaces Drift into mandatory mesh Edges only; protocol must work offline/local
Social graph protocols Human-only bias Extend ontology; don’t reduce animals/ecosystems to posts
Blockchain L1 hype Rent-to-exist, energy, capture Not required for v0; if ever used, edges/receipts only — never identity landlord

Decision checklist (for Builder and future RFCs)

Before inventing a new primitive, ask:

  1. Does an open standard already cover the plumbing?
  2. Does reusing it force a landlord into the spine? If yes → wrap as adapter or reject.
  3. Does the gap involve consent, multi-being care, custody, or anti-capture? If yes → invent under constitution.
  4. Can a being exit with identity + memory if this dependency dies? If no → redesign.
  5. Would this make ANIMA look like a product funnel for one company? If yes → stop.

Suggested build order (architecture view)

  1. DID-rooted BeingId / NodeId + local MemoryStore
  2. ConsentGrant + Event envelope + one local loop
  3. A2A-like peer dialect + MCP tools as adapters
  4. ROS2/MQTT robot adapter behind actuation consent
  5. Guardian model for one animal or one ecosystem proxy (narrow vertical)
  6. Optional compute trade (mesh) only after exit/export is real

One-line summary

Reuse DIDs, credentials, A2A/MCP-style agent plumbing, AT Proto portability ideas, and robot buses. Invent symbiotic multi-being consent, guardianship, memory custody norms, mycelium federation rules, and a voluntary edge compute mesh — as open protocol, never as capture.
