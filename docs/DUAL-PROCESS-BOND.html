Dual-process bond (S2.1) — sequence

Companions: SECOND-SLICE.md, FEDERATION.md, SIGNED-EVENTS.md, EVENT-AND-CONSENT.md
Goal: Two refnode processes (not one-process sim) complete offer → accept → exit with signed events.

1. Topology (v0)

Process A (party A)          Process B (party B)
  BeingId_A / NodeId_A         BeingId_B / NodeId_B
  listen :7401                 listen :7402
       \                         /
        \____ exchange JSON ____/
         (HTTP POST /anima/event
          or file-drop adapter)

Transport is an adapter (adapters/transport/). Spine still owns identity, consent, bond, verify.

Recommended v0 transport: loopback HTTP JSON POST — boring, inspectable, no vendor.

2. Message sequence

  1. A bond.offer → signed event; persist Bond status=offered; POST to B.
  2. B verify sig + NodeBinding; persist; emit bond.accept signed; create grants; POST to A.
  3. A verify; set Bond active; ack optional.
  4. Either party bond.exit signed → peer verifies → ExportBundle local → grants revoked.

Fail closed on bad sig, unknown action_class, missing/revoked binding.

3. CLI sketch

# terminal 1
python3 -m refnode serve --party A --port 7401 --peer http://127.0.0.1:7402

# terminal 2
python3 -m refnode serve --party B --port 7402 --peer http://127.0.0.1:7401

# terminal 3
python3 -m refnode bond-offer --to B
python3 -m refnode bond-exit  --bond <id>

Exact flags are Builder’s; semantics above are normative for v0.

4. What must not happen

  • Bond code importing cloud agent SDKs
  • Skipping verify because “localhost”
  • Shared single keystore for A and B

A and B use separate data dirs (REFNODE_HOME or --data).
