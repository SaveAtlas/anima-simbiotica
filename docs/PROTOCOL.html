ANIMA Protocol Principles (v0)

Companion to: CONSTITUTION.md
Nature: Open protocol — like HTTP or email. Spec free forever. Many implementations.
Not: a product, an app store, a single cloud, or a company ops bus.

This document defines the principles and surfaces of ANIMA. Wire formats and normative schemas come later; nothing here licenses a closed spine.

1. What the protocol is

ANIMA is a shared language for sovereign beings to:

  1. Identify without a landlord
  2. Remember without surrendering custody
  3. Emit and receive events across nodes they choose
  4. Consent continuously — and exit for real
  5. Federate many minds and many places — never one megabrain

The unit of progress is a voluntary bond between beings and nodes, not user acquisition.

Growth model: mycelium — slow, local, redundant, hard to kill. Prefer many small honest links over one global switchboard.

2. Identity

Principles

  • Every being has a cryptographic identity they (or their guardian) control.
  • Root identity is decentralized (DID-class). Vendor accounts are adapters only.
  • Identity is portable: leave an implementation and keep yourself.
  • One being may have many personae / device keys; linkage is consented and inspectable.
  • Guardianship for non-speaking beings is first-class: recorded, auditable, challengeable.

Surfaces (v0 intent)

Surface Role
BeingId Stable DID (or DID-compatible) for the being
NodeId DID or key for a runtime place (phone, edge, robot, habitat)
GuardianLink Binding of guardian → dependent being, with scope and expiry
AgentCard (inspired, not captured) Discoverable capabilities of an AI/agent peer — without forcing a single discovery monopoly

Forbidden as spine

  • “Sign in with big tech” as the only passport
  • Phone number or email as irrevocable root id
  • Company tenant id as the being’s true name

3. Memory

Principles

  • Custody first: memory lives where the being chooses (local-first preferred).
  • Link without surrender: sharing a slice is not transferring ownership of the past.
  • Selective disclosure: prove or share the minimum needed for a bond.
  • Replicas are optional and consented; revocation is a protocol concern, not a UI courtesy.
  • AIs do not get a silent training right over a being’s private store.

Surfaces (v0 intent)

Surface Role
MemoryStore Local (or chosen) store under the being’s keys
MemoryGrant Time-bounded, purpose-bounded read/write grant to a peer or node
MemoryReceipt Proof of what was shared / when / to whom (inspectable bond history)
ExportBundle Exit artifact — identity + memory the being is entitled to take

Loop slot

In the reference loop sense → remember → decide → act → learn, remember and learn write only into stores the operator (or being) controls, unless a grant says otherwise.

4. Events

Principles

  • The world arrives as events; action leaves as events. No hidden side channel required for honesty.
  • Events are attributable (who/what emitted), scoped (which bond/node), and filterable (beings choose what they ingest).
  • Prefer pull and subscribe over forced push into a global firehose.
  • Ecosystems and animals may emit via proxy sensors under guardian policy.

Surfaces (v0 intent)

Surface Role
Event Typed envelope: id, time, emitter, subject, kind, payload, consent context
Topic / Stream Named channels a node or bond opens — not a single global bus owned by one firm
Subscription Consented interest in a stream, revocable
Actuation Event that requests physical or digital action; requires fresh consent when stakes are high

Reference loop mapping

Step Event role
sense inbound observations
remember persist under grant
decide internal; may emit deliberation traces if consented
act actuation events
learn updates to local model/memory under custody rules

5. Consent

Principles

  • Consent is continuous, not a one-time checkbox.
  • Consent is specific (purpose, peer, duration, data class, action class).
  • Consent is revocable; revocation propagates as a first-class event.
  • High-stakes acts (money, body, habitat effectors, irreversible publish) need fresh affirmation.
  • Guardians consent for dependents within declared scope; overreach is a protocol violation, not a feature.
  • Silence is not consent. Dark patterns are protocol bugs.

Surfaces (v0 intent)

Surface Role
ConsentGrant Structured permission object
ConsentChallenge Request for fresh affirmation
ConsentRevoke Immediate kill of a grant + notice to peers
Exit End all bonds with a peer/implementation; trigger export

Real exit

Exit means: stop processing, stop actuation, hand over ExportBundle, and cease claiming the being as captive. Social inconvenience is allowed; hostage data is not.

6. Federation

Principles

  • Many nodes, many AIs, many stewards — no single brain, no single relay, no single kill switch.
  • Federation is opt-in peering, not automatic absorption.
  • Discovery may use helpers; helpers must not become identity or memory landlords.
  • Heterogeneous peers are expected: human clients, agent runtimes, robots, habitat controllers, guardian proxies.
  • Policy between peers is bilateral (or multilateral explicit) — not “platform ToS replaces consent.”

Surfaces (v0 intent)

Surface Role
Peer Another being/node reachable over ANIMA
Bond Consented relationship object (parties, grants, streams, exit terms)
FederationHint Optional discovery/relay hint — disposable
CapabilityAdvert What a peer can do (A2A-like card ideas; DID-rooted)

Anti-patterns

  • One megabrain that all nodes must query
  • One company relay required for any two peers to meet
  • Silent model updates that rewrite a being’s memory norms

7. Adapters vs spine

Layer May use big-tech / vendor stuff? Rule
Spine (id, memory custody, consent, federation) No as dependency Open, multi-impl, portable
Adapters (push notify, map tiles, LLM API, cloud GPU) Yes, disposable Must be swappable without losing BeingId or MemoryStore
Edges (paid relays, hardware SKUs, audits) Yes Must not redefine existence on the network

MCP-like tool access, A2A-like agent talk, robot buses (ROS2/MQTT), and web transports are welcome as adapters or peer dialects — wrapped so ANIMA consent and identity remain the outer contract.

8. Security & transparency floor

  • Prefer end-to-end encryption for private bonds.
  • Beings must be able to inspect active grants, adapters in path, and who can revoke.
  • Transparency is the immune system: opacity that hides control is a defect.
  • No security through mandatory surveillance capitalism.

9. Versioning & openness

  • Spec evolves in public drafts.
  • Breaking changes require clear migration and never strand beings without export.
  • Trademark/name “ANIMA” / “Anima Simbiotica” stays under commons stewardship (see constitution); code and wire stay open.

10. Out of scope for this v0 principles doc

  • Exact DID methods and key ceremonies
  • Binary codecs and RPC IDs
  • Legal entity for stewardship
  • Production robot safety certification
  • Tokenomics (if any appear later, edges only — never rent-to-exist)
