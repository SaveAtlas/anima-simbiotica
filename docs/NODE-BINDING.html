NodeBinding — BeingId ↔ NodeId (v0.2 target)

Status: Schema sketch for ADR-001 migration.
Companions: adr/ADR-001-being-vs-node-keys.md, EVENT-AND-CONSENT.md, FEDERATION.md
Rule: Device compromise ≠ identity death. Being root and node keys are separate.

1. Problem

Reference-node v0 uses one ed25519 key for both BeingId and NodeId (did:key + fragment). Demo-only. Multi-device, theft, and guardianship need a binding attestation.

2. NodeBinding object

{
  "id": "bind-<id>",
  "type": "NodeBinding",
  "being_id": "did:key:z...BeingRoot",
  "node_id": "did:key:z...NodeDevice",
  "node_label": "home-edge-1",
  "status": "active | revoked",
  "issued_at": "2026-09-05T04:00:00Z",
  "expires_at": null,
  "capabilities": ["sense", "remember", "decide", "act", "learn"],
  "sig_being": "<base64 ed25519 over canonical binding bytes>",
  "note": "Signed by Being root. Revoke without rotating BeingId."
}

Optional VC wrapper later (type includes VerifiableCredential); v0.2 may ship signed JSON only.

3. Verification rules

  1. sig_being verifies with BeingId verification key.
  2. Actuation events from a NodeId require an active NodeBinding to that BeingId (or explicit guardian path).
  3. Revoke → status: revoked + consent.revoke-style notice to bonded peers.
  4. Export bundle includes active bindings the being chooses to publish.

4. Key ceremony (operator sketch)

  1. Generate Being root key offline / on trusted device → BeingId.
  2. Generate Node key on device → NodeId.
  3. Being signs NodeBinding (QR / local USB / airgap paste in early demos).
  4. Store binding under identity/bindings/.
  5. Node never holds Being private key.

5. Migration from reference-node v0

Step Action
M1 Generate distinct node key; keep old key as temporary Being root
M2 Write first NodeBinding; update agent-card
M3 Events emit NodeId; subject remains BeingId
M4 Refuse act if binding missing/revoked
M5 Document revoke path in README

Do not break offline ./run.sh during migration — feature-flag dual mode until M4.
