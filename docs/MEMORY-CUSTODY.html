Memory custody (v0)

Companions: PROTOCOL.md §3, EVENT-AND-CONSENT.md, EXPORT-AND-EXIT.md
Rule: Link without surrender. Local-first. Training rights never silent.

1. Custody model

Role Meaning
Custodian Being (or guardian in scope) who controls keys to the store
Store MemoryStore on operator-chosen media (disk, phone, habitat box)
Replica Optional copy under a MemoryGrant — not ownership transfer
Receipt Inspectable record of what was shared

Default: writes go to custodian-local store. Network replicas require an active grant with data_class / purpose match.

2. MemoryGrant (subset of ConsentGrant)

Use ConsentGrant with:

  • action_class: memory.read.* or memory.write.*
  • data_class: e.g. observation, welfare, habitat.sensor
  • peer: remote BeingId when federating
  • expires_at: required for remote replicas in v0.2+

Attenuation only: a peer may re-share a narrower grant if allowed later; never expand.

3. Learn step

learn appends to local store only unless a grant explicitly allows export of learning artifacts.
Silent training on private memory for model providers = protocol violation.

4. Reference-node mapping

  • Store: remember/store/*.json
  • Grants: consent/grants/*.json
  • Export: slices landed in ExportBundle (EXPORT-AND-EXIT.md)

5. Builder next

  • Tag each remember write with data_class
  • Optional validate against consent-grant.schema.json when grant_id present
  • Exit bundle includes memory slices + receipts

6. Attenuation (S3.2)

A peer holding a memory.read.* or memory.write.* grant may only re-share a narrower grant:

  1. Shorter expires_at (or equal).
  2. Same or narrower data_class.
  3. Same or narrower purpose.
  4. Never escalate action_class (read must not become write).
  5. peer field, if set on parent, must remain that peer or a further restriction.

Re-share attempts that expand scope → deny and emit an inspectable reject receipt.

Cross-peer read sequence

  1. A issues ConsentGrant to B: memory.read.observation, purpose-bounded.
  2. B requests slice ids; A returns only matching slices + MemoryReceipt.
  3. A revokes grant → further B reads fail closed.
  4. Receipts remain in A's store for transparency.

Builder demo sketch

python3 -m refnode memory-grant-demo — two data dirs; B reads under grant; revoke; second read denied.

7. AttenuationRejectReceipt (S7)

When a re-share would expand scope, the node MUST deny and append an inspectable receipt:

{
  "type": "AttenuationRejectReceipt",
  "id": "rej_...",
  "parent_grant_id": "grant_...",
  "attempted_by": "did:key:...",
  "reason": "expires_at_longer|data_class_wider|purpose_wider|action_class_escalate|peer_escape",
  "at": "2026-09-05T00:00:00Z"
}

Rules:

  • Receipts are local-first transparency; they are not consent.
  • consent-inspect MUST list reject receipts alongside grants.
  • No silent drop — deny without receipt is a protocol defect.

Builder demo (S7.2)

python3 -m refnode memory-grant-attenuate-deny — attempt wider expires_at or write-from-read; expect deny + receipt; second attempt still denied.
